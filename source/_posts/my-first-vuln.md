> 讲一下我挖到的第一个漏洞是怎么样的，希望可以给到各位一些思路。
> 文中域名统一写作 `xxx.edu.cn`，截图里的域名、IP 和个人隐私信息均已打码。

## 开局只有一个登录框

{% asset_img img1.png %}

登录框开局，一开始刚点进去的时候是这样的。

思路还是老一套：踩点 → 打点 → 逻辑。

但这个站**明显没有什么逻辑可以打**——就一个登录框，还带滑块验证；外围打点也翻了一圈，好像没有什么点可以出洞。

不过有个细节很扎眼：如果直接访问 `http://xxx.edu.cn:8080/`，后台的 html 页面会**先渲染出来**，然后前端才开始检查鉴权、跳转到 `/login.html`。

## 为什么会这样：后台页面被当成了静态资源

顺着这个线索往下走，路径很清楚：`Home.html` → js 文件 → api 接口 → 文件上传接口。

```bash
curl -s -k http://xxx.edu.cn:8080/
```

直接 200，返回的是完整后台首页 HTML。

这是**开发配置错误**导致的问题：服务端根本没鉴权——后台主页面被当成静态资源直接返回 200，前端 JS 发业务请求拿到"账号异常"之后，才被动地跳登录页。

这个差别其实很大。本来你只能卡在登录框附近，能测的只有登录框这一个交互点——SQL 注入、审 JS、目录扫描，出洞概率低得多；而现在等于把整个后台的页面结构、菜单、业务模块都摆到你面前了。

## 进后台：用 Burp 卡住页面

{% asset_img img2.png %}
{% asset_img img3.png %}

页面会跳登录，所以这里进去之后用 Burp 抓包把页面卡住，看清楚有哪些请求。

**要注意：包要全部放掉**，不然会因为没权限被强制跳回登录页。

## 翻 JS：找到未鉴权的 .do 接口

{% asset_img img4.png %}

分析业务页面的 js，能翻出更多业务 html 页面，也就能进一步判断这套系统到底是干什么的。

`.do` 接口——很经典的 Struts。

{% asset_img img5.png %}
{% asset_img img6.png %}

进到 `home.html` 之后，思路是这样的：**我们是没有带 token 过来的**，那就可以去找那些未鉴权的 `.do` 接口，直接打未授权访问。后台这么多业务接口，大概率有漏鉴权的。

{% asset_img img7.png %}

这里又拿到了一堆业务 html。

最终找到这么一条：

```text
https://xxx.edu.cn:8090/work/asd/consultHelp/exportExcel.do?studentId=
```

很明显的导出接口，`studentId` 对应的值应该就是学号。

## 第一个洞：未授权导出学生信息

{% asset_img img8.png %}

该地址存在**未授权导出**功能，可导出学生信息：学号、姓名、手机号、咨询内容。

而且 `studentId` 是可以遍历的——猜到学号的构成规则，就能把学生的手机号一个个拉下来。同类的还有三个：

```text
https://xxx.edu.cn:8090/work/asd/student/exportStandardExcel.do
https://xxx.edu.cn:8090/work/asd/student/exportNotStandardExcel.do
https://xxx.edu.cn:8090/work/asd/student/exportEduEffectExcel.do
```

{% asset_img img9.png %}

## 更严重的：57 万个文件路径，全部可访问

这条接口还顺带暴露了文件路径——统计下来 **578,816** 个路径、**166,747** 个文件。

而文件就放在 `http://xxx.edu.cn:8080/upload/` 路由下，**web 可以直接访问**，这是重大问题。

{% asset_img img10.png %}

按路由前缀做了个分类统计，发现 `/studentloan/receipt/scanned` 这个前缀下的文件全都是资助/贷款回执单，里面都带身份证信息，还有银行卡号之类的。**光这一个前缀，就是 15,640 条身份证信息。**

因为这套系统本身就是资助系统，学生上传的文件里本来就有些是敏感材料：身份证、回执单、家庭情况说明……

## 结果

{% asset_img img11.png %}

喜提一个高危（Rank 5）。

回头看，就是这么一个小小的"页面没鉴权"，滚出了后面一连串的东西：一个未鉴权的静态页面 → 完整的后台业务地图 → 未授权的导出接口 → 57 万条文件路径 → 上万份带身份证的回执单。

所以挖 SRC 还是要细心、耐心地一个点一个点地看。现在网络安全普及得很广，很难再遇到那种到处都是漏洞的站点了，每一个漏洞都要用心去对待，才挖得出来。

> 文中所有域名、IP、学号、姓名、手机号、身份证号均已打码或替换为占位符；
> 测试过程仅验证了未授权访问与导出功能的存在，未批量下载、未留存任何个人数据。
